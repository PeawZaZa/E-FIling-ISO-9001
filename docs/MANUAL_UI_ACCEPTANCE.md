## 1. วัตถุประสงค์และขอบเขต

เอกสารนี้ใช้ตรวจรับ MVP ผ่านหน้าจอจริง ตั้งแต่เข้าสู่ระบบ ทะเบียนเอกสาร DAR การรับทราบ Records/Evidence รอบตรวจ/Finding CAR/NCR และ Dashboard 6 หมวด โดยเรียงขั้นให้ข้อมูลที่สร้างแล้วถูกนำไปใช้ต่อ ลดการสร้างข้อมูลซ้ำ

ข้อจำกัดของการทดสอบรอบนี้:

- ไม่ย้อนทำ Integration/Hardening หรือ System/API E2E
- ไม่เปลี่ยน business rule, permission, segregation of duties หรือ auditor independence
- CAR/NCR ทดสอบเฉพาะกติกาที่ยืนยันแล้ว และหยุดที่ `PENDING_CLOSURE` เพราะผู้มีอำนาจปิดใบยังเป็น TBD
- ห้ามใช้ DCC เป็นผู้แจ้ง Finding สำหรับเส้นทางที่ต้องจบการตรวจประสิทธิผล เพราะผู้ตรวจแทนยังเป็น TBD
- หากพบพฤติกรรมผิดคาด ให้บันทึกหลักฐานและหยุดเฉพาะ test case นั้น ห้ามแก้ข้อมูลผ่าน API/ฐานข้อมูลเพื่อข้ามขั้น

## 6. เกณฑ์การยอมรับ

ยอมรับรอบ Manual UI Acceptance เมื่อ:

- Test case ที่อยู่ในขอบเขตทั้งหมดมีผล `PASS` หรือมี `N/A` ที่อ้างอิง limitation/TBD ชัดเจน
- ไม่มี FAIL ระดับที่ทำให้ workflow หลักหยุด, ข้อมูลข้ามสิทธิ์, ไฟล์เปิดไม่ได้, หรือสูญเสีย segregation/auditor independence
