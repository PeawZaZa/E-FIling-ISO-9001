สถานะปัจจุบัน: ฉบับร่าง ยังไม่เป็น Baseline Candidate ยังไม่เป็น Approved Baseline ยังไม่ใช่ผลยอมรับโดยผู้ใช้จริงขั้นสุดท้าย

ตรวจเทียบ SRS กับเอกสารต้นทาง มติที่ยืนยันแล้ว ขอบเขต MVP และหลักฐานจากระบบ/การทดสอบ โดยคงข้อกำหนดที่ยืนยันแล้วไว้ หากระบบยังไม่ตรง ให้บันทึกเป็น implementation discrepancy ไม่แก้ข้อกำหนดตามโค้ด

ยังต้องให้อาจารย์ที่ปรึกษา เจ้าของโครงงาน และผู้ใช้ทบทวนประเด็นนโยบาย ขอบเขต และผลประเมินจริงก่อนกำหนด baseline

ความสอดคล้องกับมติ MVP

CONFIRMED QMR อนุมัติแผน CAR/NCR ในระบบทดลอง โดยผู้จัดทำไม่อนุมัติแผนตนเอง; ขั้นปัจจุบันจบที่ PENDING_CLOSURE

เอกสาร PDF ใช้การดาวน์โหลดตามสิทธิ์; การรับทราบต้องยืนยันแยกจากการดาวน์โหลด; Dashboard กรองตามบทบาท และ Sponsor เห็นภาพรวมเท่านั้น

TBD อำนาจปิด CAR/NCR และผู้ตรวจแทนกรณี DCC เป็นผู้แจ้ง Finding ยังไม่ยุติ

แยกขอบเขตและสถานะให้ชัด

คงเป้าหมายโครงงานระยะเต็มไว้ แต่ระบุส่วนที่เป็น MVP ส่วนที่พักไว้ และเรื่องที่ยังรอมติแยกกัน

  • DEFERRED เช่น export และตัวชี้วัด Dashboard ขั้นสูง ไม่ถือว่าผ่าน MVP
  • เรื่องอำนาจที่ยังไม่ตัดสินเป็น TBD
  • ข้อกำหนดที่ยืนยันแล้วแต่ระบบยังไม่ตรง ถูกบันทึกเป็น discrepancy

เหตุใดจึงยังเป็น Working Draft

ความครบถ้วนของโครงสร้างเอกสารไม่ใช่การอนุมัติข้อกำหนด ยังมีมตินโยบายและอำนาจที่เปิดอยู่ และต้องทบทวนกับอาจารย์ เจ้าของโครงงาน และผู้ใช้

ผลทดสอบ UI มี 3 กรณี BLOCKED; ยังมี implementation discrepancies ที่ต้องแก้หรือรับมติเปลี่ยนข้อกำหนดอย่างเป็นทางการ และยังไม่มีการประเมินโดยผู้ใช้จริงขั้นสุดท้าย

สคริปต์สรุปสำหรับอธิบายอาจารย์

“อาจารย์ครับ/ค่ะ พวกเรากลับมาตรวจ SRS อีกครั้ง เพราะเมื่อระบบต้นแบบและการทดสอบ UI คืบหน้าแล้ว พบว่าข้อความบางส่วนใน SRS เดิมยังเป็นข้อสมมติ หรือใช้ขอบเขตของโครงงานเต็มกับ MVP ปะปนกัน อีกทั้งเอกสารฉบับรวมเคยมีความเสี่ยงที่รายละเอียด Use Case ถูกตัดทอน จึงต้องตรวจทั้งเนื้อหาและกระบวนการสร้างเอกสารให้เชื่อถือได้ครับ/ค่ะ

การปรับครั้งนี้ไม่ได้เปลี่ยนข้อกำหนดเพียงเพื่อให้ตรงกับโค้ด เราเทียบเอกสารต้นทาง มติที่ยืนยันแล้ว และขอบเขต MVP กับหลักฐานจากระบบและผลทดสอบ แล้วแยกสิ่งที่ยังไม่ตรงเป็น implementation discrepancy ส่วนเรื่องที่ยังไม่มีผู้มีอำนาจตัดสินก็ยังระบุเป็น TBD ฉบับ 1.2 จึงมีโครงสร้างครบส่วนที่ 1 ถึง 6 ภาคผนวก A ถึง F และ Use Case ทั้ง 28 ข้อ พร้อมการตรวจไม่ให้ตัวสร้างตัดเนื้อหาอีก ตัวอย่างมติ MVP ที่ชัดขึ้นคือ QMR อนุมัติแผน CAR/NCR ระบบปัจจุบันไปถึง PENDING_CLOSURE, PDF ใช้ดาวน์โหลดตามสิทธิ์ และการรับทราบต้องยืนยันแยกจากการดาวน์โหลดครับ/ค่ะ

ผล Manual UI Acceptance ปัจจุบันคือผ่าน 136 กรณี ไม่มี FAIL และ BLOCKED 3 จาก 139 กรณี โดยสามกรณีที่ค้างขาดข้อมูลทดสอบคู่ความขัดแย้งด้านความเป็นอิสระของผู้ตรวจ ไม่ใช่ผลว่าระบบล้มเหลว อย่างไรก็ตาม ผล UI นี้ยังไม่ใช่การยอมรับขั้นสุดท้ายโดยผู้ใช้จริง และ SRS ยังเป็น Working Draft เพราะอำนาจปิด CAR/NCR กับผู้ตรวจแทนกรณี DCC เป็นผู้แจ้ง Finding ยังต้องมีมติ รวมทั้งต้องทบทวนความสัมพันธ์ระหว่างเป้าหมายบทที่ 1 กับ MVP ต่อไปครับ/ค่ะ

ขั้นถัดไปตามคำแนะนำอาจารย์ เราจะสอบกลับ Use Case ทั้ง 28 ข้อจาก Requirement และ Business Rule ผ่านขั้นตอน หน้าจอ ข้อมูลหรือ ERD เกณฑ์ยอมรับ ไปถึงผล implementation และ test แล้วจัดสถานะอย่างตรงไปตรงมา ตารางนี้จะเป็นหลักฐานสำหรับบทที่ 4 และ 5 ซึ่งยังไม่ควรถือว่าสรุปสมบูรณ์จนกว่าอาจารย์และผู้ใช้จะทบทวน พร้อมมีการประเมินโดยผู้ใช้จริงครับ/ค่ะ”
