# ระบบ E-Filing — ISO 9001:2015

ระบบบริหารงานคุณภาพ สำนักงานคณบดีคณะวิศวกรรมศาสตร์ มหาวิทยาลัยเทคโนโลยีราชมงคลล้านนา

โครงงานปริญญานิพนธ์ SE02 · กลุ่ม A ควบคุมเอกสาร/DAR/การรับทราบ · กลุ่ม B หลักฐาน/การตรวจติดตาม/ใบคำร้อง/แดชบอร์ด

## สิ่งที่ต้องมีก่อน

- Node.js 20 ขึ้นไป (ทดสอบด้วย 26)
- PostgreSQL 17 — ในเครื่องพัฒนาปัจจุบันใช้ชุดไฟล์แบบพกพา ไม่ต้องใช้สิทธิ์ผู้ดูแลระบบ

## เริ่มใช้งาน

```bash
cp .env.example .env        # แก้ค่าตามเครื่อง โดยเฉพาะ JWT_SECRET
./scripts/db-start.sh       # เริ่มฐานข้อมูล
npm install
npm run db:migrate          # สร้างตาราง
npm run db:seed             # ข้อมูลตั้งต้น บทบาทและบัญชีตัวอย่าง
npm run dev                 # ส่วนให้บริการข้อมูลที่พอร์ต 4000
```

บัญชีตัวอย่างทุกบัญชีใช้รหัสผ่าน `efiling1234` ดูรายชื่อได้ใน `prisma/seed.ts`

ตรวจว่าระบบขึ้นแล้วและกำลังใช้ข้อกำหนดชุดใด

```bash
curl http://localhost:4000/health
```

## Policy Pack — จุดที่ข้อกำหนดสองฉบับขัดกัน

`SRS_A+B.md` (ฉบับรวมของกลุ่ม A) ขัดกับแบบเสนอหัวข้อ SE02 และบทที่ 1 ที่อนุมัติไปแล้ว
ในสามเรื่อง ซึ่งยังตกลงกันไม่ได้ ทั้งสามเรื่องเป็นข้อมูล ไม่ใช่ตรรกะ จึงถูกดึงออกมาไว้
ใน `packages/policy/` แยกเป็นสองแพ็ก สลับด้วยตัวแปรเดียว

| | `variant-srsab` (ค่าตั้งต้น) | `variant-proposal` |
|---|---|---|
| ที่มา | `SRS_A+B.md` v0.12 | แบบเสนอหัวข้อ SE02 · บทที่ 1 |
| สถานะใบคำร้อง | 5 สถานะ มี Reopened | 4 สถานะ ทวนสอบไม่ผ่านย้อนกลับไปกำลังดำเนินการ |
| บทบาทผู้ใช้ | 10 บทบาท | 4 บทบาท |
| ผู้ปิดใบคำร้อง | QMR หรือ Lead Auditor | Auditor หรือ ISO/QA |
| อ่านข้อมูลกลุ่ม A | เรียกฟังก์ชันในกระบวนการเดียวกัน | เรียกผ่าน API อ่านอย่างเดียว |

```bash
POLICY_VARIANT=proposal npm run dev
```

รายละเอียดข้อขัดแย้งและจุดยืนของกลุ่ม B อยู่ใน `../SRS_AB_Review.md`

**กฎที่ห้ามฝ่าฝืน** ห้ามเขียนชื่อสถานะใบคำร้องหรือชื่อบทบาทเป็นค่าคงที่ในโค้ดนอก
`packages/policy/` เพราะจะทำให้สลับแพ็กแล้วพังเป็นจุด ๆ โดยไม่มีอะไรเตือน
ตรวจได้ด้วย

```bash
grep -rn "Pending Verify\|Reopened\|ISO_QA_ADMIN" --include=*.ts apps
```

## รายการตรวจสอบและการสอบกลับ

```bash
npm run trace
```

อ่าน `packages/traceability/traceability.yaml` ซึ่งสกัดมาจาก `SRS_A+B.md`
แล้วสแกนความเห็น `@trace` ในโค้ดจริง สร้างสองไฟล์

- `docs/CHECKLIST.md` เข้า git ดูส่วนต่างได้เมื่อความคืบหน้าเปลี่ยน
- `docs/checklist.html` เปิดดูในเบราว์เซอร์

ทั้งสองไฟล์สร้างจากสคริปต์ **ห้ามแก้ด้วยมือ** เวลาทำงานเสร็จให้กำกับไว้ในโค้ด

```ts
/** @trace UC-10 FR-B06 */
export async function openCar() { ... }
```

และในไฟล์ทดสอบให้กำกับเกณฑ์การยอมรับด้วย เช่น `@trace AC-08`
สถานะจึงสะท้อนงานจริงเสมอ ทำเขียวปลอมไม่ได้

## โครงสร้าง

```
apps/api                ส่วนให้บริการข้อมูล — Express + Prisma
  src/modules/shared      ยืนยันตัวตน สิทธิ์ ร่องรอยการตรวจสอบ การจัดเก็บข้อมูล
  src/modules/groupA      ควบคุมเอกสาร DAR การรับทราบ (UC-01–07, UC-16)
  src/modules/groupB      หลักฐาน การตรวจติดตาม ใบคำร้อง แดชบอร์ด (UC-08–13)
apps/web                ส่วนติดต่อผู้ใช้ — React
packages/policy         ข้อกำหนดที่สลับได้ระหว่างสองฉบับ
packages/traceability   สายโยงและตัวสร้างรายการตรวจสอบ
prisma                  โครงฐานข้อมูลและข้อมูลตั้งต้น
scripts                 จัดการฐานข้อมูลแบบพกพา
```

## คำสั่งที่ใช้บ่อย

|---|---|
| `npm run dev` | เริ่มส่วนให้บริการข้อมูล |
