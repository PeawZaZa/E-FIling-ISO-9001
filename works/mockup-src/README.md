# E-Filing MVP Mockup

ไฟล์เปิดใช้งาน: `../E-Filing ISO (MVP Mockup).html` — เปิดไฟล์เดียวใน browser ได้ ไม่ต้องเปิด server และไม่ต้องต่ออินเทอร์เน็ต ไลบรารีกับฟอนต์นำจาก bundle ใน Standalone เดิม โดยไม่ได้แก้ต้นฉบับ

## ขอบเขตที่กดทดลองได้

- เลือกคนเดโมครบ 14 บทบาท เติมบัญชีให้ และสลับคนจากส่วนหัว เมนู/คำสั่งเปลี่ยนตามบทบาท
- ทะเบียนเอกสาร ค้นหา/กรอง เปิดรายละเอียดและไฟล์ PDF
- นำเข้าฉบับประกาศใช้เดิม QM/QP/WI/SD/FM ด้วยรหัสเดิม โดย DCC
- เจ้าของเอกสารยื่น DAR พร้อม PDF; DCC ตรวจรับ → ผู้ทบทวน → QMR → DCC ประกาศใช้ → ผู้คุมทะเบียนแนบหลักฐานและปิด DAR
- จัดทำใหม่ใช้รหัส QP จำลอง เริ่มลำดับ 90; แก้ไขฉบับเดิมคงรหัส เพิ่ม Rev และเก็บไฟล์ฉบับก่อนหน้า
- QM: DCC จัดทำ → QMR ทบทวน → คณบดีอนุมัติ; QP/WI: รองคณบดีทบทวน → QMR อนุมัติ ส่วน SD/FM ยื่นและตรวจรับได้ แต่อำนาจยังรอยืนยัน
- การรับทราบต่อฉบับ บันทึก/หลักฐาน รอบตรวจ Finding เปิด CAR/NCR และป้องกันเปิดใบค้างซ้ำจาก Finding
- CAR: แก้เฉพาะหน้า → สาเหตุ/แผน → อนุมัติ → ผลดำเนินการพร้อมไฟล์ → ตรวจประสิทธิผล → รอปิด พร้อมส่งกลับและประวัติ
- Dashboard คำนวณจากรายการที่บัญชีเดโมเห็น และคลิกลงรายการได้

## วิธีลอง DAR

1. เลือกเจ้าของเอกสาร → ยื่น DAR → เลือก QP กรอกข้อมูลและแนบ PDF
2. สลับเป็น DCC เปิดคำขอ → ตรวจรับครบ
3. สลับผู้อนุมัติเอกสาร / รองคณบดี → ทบทวนผ่าน
4. สลับ QMR → อนุมัติ
5. สลับ DCC → เปิด DAR → ไปประกาศใช้ → ยืนยันประกาศใช้
6. เอกสารเข้าทะเบียนพร้อมไฟล์เดิม; สลับผู้คุมทะเบียน DAR → ตรวจรายการแจกจ่าย/เรียกคืน แนบหลักฐาน → ปิด DAR

## ข้อจำกัดที่แสดงในหน้าจอ

- ข้อมูลและไฟล์อยู่ในหน่วยความจำของหน้า รีโหลดแล้วเริ่มใหม่ ไม่มีการส่งไฟล์ไป server และไม่มีฐานข้อมูล
- การเลือกไฟล์เป็นต้นแบบฝั่ง browser ไม่ใช่การยืนยันระบบจัดเก็บไฟล์หรือ security ของระบบจริง
- บัญชีเดโมไม่ใช่ระบบ authentication; กฎสิทธิ์ในต้นแบบไม่ทดแทนการตรวจสิทธิ์ฝั่ง server
- รหัสลำดับเป็นตัวอย่าง ไม่ใช่การจองเลขทะเบียนจริงหรือการกันซ้ำเมื่อใช้หลายคน
- จำนวนผู้ลงนามปิด CAR ยังรอยืนยัน จึงปิดด้วยคำสั่งจริงในเดโมไม่ได้ มีตัวอย่างใบปิดแยกชัดเจน ไม่ใช้แทนผลอนุมัติ
- การมอบหมายรับทราบใหม่ยังรอยืนยันอำนาจ ใช้รายการตั้งต้น; ยังไม่มีจัดการผู้ใช้ ค้น Audit Trail รวม ส่งออกรายงาน หรือยกเลิกเอกสาร
- แผน CAR แสดงเป็นข้อความสรุปในต้นแบบ ยังไม่ใช่แบบฟอร์มหลายกิจกรรมครบตาม SRS
- สถานะ วันที่ และชื่อในข้อมูลตั้งต้นเป็นข้อมูลสาธิต ไม่ใช่ทะเบียนหน่วยงานที่รับรองแล้ว

## แก้ไข / สร้างไฟล์ใหม่

แก้ `app.jsx` และ `style.css` แล้วเรียกจากราก repo:

```text
python works/mockup-src/build.py
```

ต้องมี Python และ Node; build อ่าน React/Babel/ฟอนต์จาก Standalone เดิมโดยไม่ดาวน์โหลด package เพิ่ม จากนั้น compile JSX และฝังทุกอย่างลง HTML ผลลัพธ์

ตรวจด้วย Chromium เมื่อ 17 กันยายน 2569: นำเข้า WI, DAR จนปิด, CAR ถึงรอปิด, รับทราบ, เพิ่ม Record/Finding, เมนูตามบทบาท และหน้าจอมือถือ ไม่พบ JavaScript runtime error ในเส้นทางที่ตรวจ


## บทบาทครบ 14 — ปรับ 17 กันยายน 2569

เพิ่ม Sponsor, ผู้ช่วย QMR, หัวหน้างาน, Lead Auditor, Assistant DCC และคณบดี ให้ครบตามทะเบียนกลาง

- Sponsor เห็นเฉพาะค่าสรุป ไม่มีลิงก์เจาะข้อมูลรายบุคคล
- QMR มอบหมายผู้ช่วย QMR เป็นราย DAR/ใบคำร้องและถอนการมอบหมายได้ ผู้ช่วยเห็นเฉพาะรายการที่ได้รับมอบหมาย การทำรายการบันทึกบัญชีผู้ช่วยเอง
- หัวหน้างานอ่านงานของกลุ่มงานตัวอย่าง และบันทึกความเห็นต่อแผนโดยไม่เปลี่ยนผลอนุมัติ
- Lead Auditor สร้างรอบตรวจ บันทึก Finding และมอบหมายผู้ตรวจประสิทธิผล อำนาจอนุมัติแผน/ปิดที่ยังขัดกันคงเป็นรายการรอยืนยัน
- Assistant DCC เห็นและตรวจได้เฉพาะใบที่มอบหมายให้ตน โดยต้องไม่เป็นผู้แก้ไข และไม่มีสิทธิ์ปิด
- คณบดีเห็น QM และอนุมัติหลังผ่านทบทวน ไม่ได้สิทธิ์ Sponsor/QMR เพิ่มโดยอัตโนมัติ
- CAR Owner ไม่ได้รับเมนู Dashboard หรือรับทราบโดยอัตโนมัติ ผู้ใช้โมดูล B เปิดเอกสารผ่านรายการอ้างอิงที่เกี่ยวข้อง ไม่ได้รับทะเบียนเอกสารทั้งหมด

การมอบหมายใน mockup เป็นตัวอย่างแบบรายรายการ ยังไม่ใช่การออกแบบขอบเขตและอายุการมอบหมายครบทุกกรณีตามระบบจริง ข้อมูลตัวอย่างของ Lead Auditor / หัวหน้างานอยู่ในรอบตรวจ/กลุ่มงานที่บัญชีนั้นรับผิดชอบทั้งหมด

ทดสอบเพิ่มเติมผ่าน: เลือกครบ 14 บัญชี เมนูตามบทบาท QM ตั้งแต่ DCC จัดทำถึงคณบดีอนุมัติและประกาศใช้ มอบหมาย/ถอนสิทธิ์ผู้ช่วย QMR ผู้ตรวจที่มอบหมาย และ Sponsor ดูเฉพาะสรุป

## Dashboard ทั้งระบบ — 17 กันยายน 2569

หน้าภาพรวมมี 6 หมวด: เอกสาร (ประเภท/สถานะ/ฉบับก่อนหน้า), การรับทราบ, บันทึกและไฟล์หลักฐาน, รอบตรวจ/Finding, DAR และ CAR/NCR คำนวณจาก state ปัจจุบันและขอบเขตบัญชีเดียวกับหน้ารายการ

Sponsor เห็นเฉพาะตัวเลขรวม ไม่กดเข้ารายการ ผู้ช่วย QMR เห็นเฉพาะงานมอบหมาย บทบาทที่ไม่มีสิทธิ์เห็นหมวดใดแสดงข้อความไม่มีสิทธิ์แทนเลขศูนย์ การรับทราบของผู้ปฏิบัติงานนับเฉพาะบัญชีตน ไม่เปิดข้อมูลรายบุคคลอื่น เมนู Dashboard ยังใช้ชุดบทบาทที่กำหนดเดิม

DAR แสดงส่งกลับให้แก้ไขและทั้ง 6 ขั้น กดลงรายการพร้อมตัวกรองสถานะได้ หลักฐานนับ URL ของไฟล์แนบที่ไม่ซ้ำใน Record/Finding/CAR ไม่รวมไฟล์เอกสารควบคุม; รอบตรวจและ Finding ยังไม่สมมติสถานะที่ไม่มีในข้อมูล mockup

ตรวจ Chromium: ครบทุกหมวด ตัวเลขตั้งต้น ลิงก์กรอง DAR ขอบเขต Sponsor/Auditor/ผู้ช่วย QMR และความกว้างมือถือผ่าน ไม่พบ JavaScript runtime error
