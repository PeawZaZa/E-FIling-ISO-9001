# practice/ — พื้นที่ฝึกก่อนลงมือพัฒนาจริง

โฟลเดอร์นี้ **ไม่ใช่ระบบจริง** เป็นที่ทบทวนและฝึกใช้เครื่องมือก่อนเริ่มพัฒนา
โค้ดที่เขียนในนี้ทิ้งได้ ยกเว้นโมดูล 07 ที่ออกแบบให้ต่อยอดเป็นโครงเริ่มของระบบจริงได้

---

## เริ่มตรงนี้

เปิด **`tutorial.html`** ด้วยเบราว์เซอร์ ดับเบิลคลิกได้เลย ไม่ต้องติดตั้งอะไร

| โมดูล | เนื้อหา | จำนวนข้อ |
|---|---|---:|
| 00 | ตั้งเครื่องให้พร้อม | 2 |
| 01 | จาวาสคริปต์เท่าที่โครงงานนี้ใช้ | 5 |
| 02 | PostgreSQL กับ Prisma | 6 |
| 03 | Express กับการแบ่งสามส่วน | 5 |
| 04 | สิทธิ์และร่องรอยการตรวจสอบ | 6 |
| 05 | React ฝั่งหน้าจอ | 5 |
| 06 | Chart.js กับแดชบอร์ด | 4 |
| 07 | ข้อสอบรวม — บันทึกข้อมูลและแนบหลักฐาน | 5 |
| | **รวม** | **38** |

ความคืบหน้าบันทึกไว้ในเบราว์เซอร์ที่เปิด ปิดแล้วกลับมาทำต่อได้
ถ้าเปลี่ยนเครื่องหรือเปลี่ยนเบราว์เซอร์จะเริ่มนับใหม่

**อ่านแล้วทำแบบฝึกหัดทันที อย่าอ่านรวดเดียวจบ** เนื้อหาออกแบบมาให้นึกคำตอบเองก่อนดูเฉลย
เพราะปัญหาที่ตั้งใจแก้คืออ่านโค้ดออกแต่เขียนเองไม่ได้ ซึ่งการอ่านผ่านไม่ช่วยเลย

## ตั้งเครื่องก่อนเริ่มโมดูล 02

โมดูล 00 และ 01 อ่านอย่างเดียวก็ทำได้ แต่ตั้งแต่โมดูล 02 ต้องมีของจริง

```bash
# ตรวจว่าลงครบแล้ว
node -v          # ต้องเป็นรุ่น LTS เลขคู่ เช่น v22.x
npm -v
psql --version   # ต้องเป็น 16 ขึ้นไป
```

```bash
# ในโฟลเดอร์ practice/ นี้
mkdir api web

cd api
npm init -y
npm install express cors dotenv
npm install --save-dev nodemon
npm install prisma --save-dev
npm install @prisma/client
npx prisma init

cd ../web
npm create vite@latest . -- --template react
npm install
npm install chart.js react-chartjs-2
```

จากนั้นแก้ `api/.env` ให้ชี้ไปฐานข้อมูลของตัวเอง

```
DATABASE_URL="postgresql://postgres:รหัสผ่าน@localhost:5432/efiling_practice?schema=public"
```

> ⚠️ **ห้าม commit ไฟล์ `.env`** เพราะมีรหัสผ่านฐานข้อมูล
> `.gitignore` ในโฟลเดอร์นี้กันไว้แล้ว แต่ตรวจก่อน commit ครั้งแรกทุกครั้ง

## โครงโฟลเดอร์ที่จะสร้างระหว่างฝึก

โครงนี้มาจาก **ADR-05** ที่กำหนดให้แบ่งความรับผิดชอบในโค้ดเป็นสามส่วน

```
practice/
├─ tutorial.html          ← เว็บติว เปิดด้วยเบราว์เซอร์
├─ api/
│  ├─ prisma/
│  │  ├─ schema.prisma    ← แหล่งความจริงเดียวของโครงสร้างข้อมูล
│  │  └─ migrations/      ← ต้อง commit ขึ้น git ด้วย
│  └─ src/
│     ├─ routes/          ← ผูก URL กับตัวจัดการ
│     ├─ controllers/     ← แกะค่าจากคำขอ ห้ามมีกฎทางธุรกิจ
│     ├─ services/        ← กฎทางธุรกิจทั้งหมดอยู่ที่นี่
│     ├─ repositories/    ← คุยกับฐานข้อมูลอย่างเดียว
│     └─ middleware/      ← ตรวจตัวตนและสิทธิ์
└─ web/
   └─ src/
      ├─ components/
      └─ constants/       ← ตารางแปลงรหัสเป็นชื่อไทย เก็บที่เดียว
```

## กฎที่ยกมาจากเอกสารข้อกำหนด ใช้ตอนฝึกด้วย

ฝึกให้ติดนิสัยตั้งแต่ตอนนี้ เพราะพอขึ้นของจริงจะไม่ต้องมาแก้นิสัย

| กฎ | ที่มา |
|---|---|
| หน้าจอแสดง **ชื่อไทย** เท่านั้น รหัสอังกฤษใช้ได้เฉพาะในฐานข้อมูลและส่วนเชื่อมต่อ | `NFR-B-02` (ก) |
| **ห้ามมีกฎทางธุรกิจในชั้นรับคำขอ** | `NFR-B-04` (ก) |
| สิทธิ์คิดจาก **บทบาทใช้งานปัจจุบัน** ไม่ใช่ผลรวมของทุกบทบาทที่ถือ | `BR-B-10` |
| กรองสิทธิ์ตั้งแต่ชั้นข้อมูล **ห้ามส่งข้อมูลเกินสิทธิ์ไปให้หน้าเว็บซ่อน** | `NFR-B-01` (ค) |
| ค่ากำหนดเวลาและเพดานไฟล์ **ต้องปรับได้โดยไม่แก้โปรแกรม** | `BR-B-16` |
| ทุกเหตุการณ์สำคัญต้องมีร่องรอย พร้อม **บทบาทขณะกระทำ** | `NFR-B-01` (จ) |
